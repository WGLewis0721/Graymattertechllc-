# Process & Documentation Starter Kit

## Who it is for

"Everything important is in someone's head."

A business where training a new person means shadowing the owner for weeks, every
hand-off needs the same explanation again, and one absence would stall the work.
The procedures exist only as memory, scattered files, or "just ask Mike."

## Fit check

1. Which 3 to 5 jobs does the business repeat most, and who does each one today?
2. Is anyone hired or handed work in the next 90 days? (Sets the urgency.)
3. Where do procedures live now: old files, email, phone screenshots, or nowhere? Ask the owner to show two examples.
4. Which shared drive does the client use and own: Google Drive or Microsoft 365 / SharePoint?
5. Is the owner available for an interview and a recorded walkthrough of each job?
6. Who will keep the documents current after handoff, and how often will they review them?

**Disqualifier:** the owner wants the documents kept in a drive or account that Gray Matter, not the client, owns. Decline that setup. The client's drive is the only home for the SOPs.

## Scope included

- A short owner interview that lists the in-scope jobs and their owners.
- One recorded walkthrough per job, with the owner's narration.
- One written SOP per in-scope job, using `SOP_TEMPLATE.md` in this kit.
- One tested run of each SOP by a second person, with gaps fixed.
- A folder structure in the client's shared drive, with one current version of each SOP.
- A short "how to keep it current" note for the client's named owner.

## Scope excluded

- Process maps, checklists, runbooks, and a searchable knowledge base beyond the in-scope jobs. Quoted separately.
- Automating any step. Automation is a separate service (`workflow-automation`) and comes after the SOPs are tested.
- Software or a wiki platform the client does not already own.
- Ongoing document updates after handoff, unless quoted under a support arrangement.

## Client inputs

- A named owner who can answer questions about each job.
- Access to the client's shared drive, as an editor invitation or with the client creating the folders.
- Time for interviews and one recorded walkthrough per job.
- A named second person for each SOP test run, who has never done that job.
- Any existing files about the jobs, even if messy.

## Default stack

- The client's shared drive: Google Drive or Microsoft 365 / SharePoint, already paid for by the client. No new paid tool.
- Documents: Google Docs or Word, in the same shared drive.
- Recording: the screen recorder built into the client's operating system, or a free recorder. Store recordings in the same drive. No paid recording tool is needed.
- Templates: `SOP_TEMPLATE.md` in this kit, copied into the client's drive as a Google Doc or Word file.

## Build steps

1. Interview the owner in one session. List the in-scope jobs, who does each one, and how often.
2. Confirm the list with the owner. Mark each job as in scope or out of scope for this kit.
3. Create the folder structure in the client's shared drive, one folder per job, plus a folder named "Current" for final SOPs.
4. Record one walkthrough per job. Ask the owner to do the job once, narrating each step out loud. Save the recording in the job's folder.
5. Write a draft SOP for each job from the recording, using `SOP_TEMPLATE.md`. Keep each step to one action.
6. Review each draft with the owner. Ask "what would go wrong here?" and add each answer to the "When it goes wrong" table.
7. Pick a second person who has never done the job. Give them only the SOP and the materials it lists. Ask them to complete the job with no help.
8. Watch the test run. Note each point where they stop, guess, or ask a question. Do not help unless they are stuck and cannot continue.
9. Fix each gap in the SOP. Record the change in the change log. Repeat step 7 until the second person completes the job without help.
10. Move each final SOP into the "Current" folder. Retire older copies by moving them to an "Archive" folder. Do not keep two current versions.
11. Write the "how to keep it current" note: the named owner, the review date, and where changes are logged.
12. Hand over the folder, the owner's access, and the note in one session with the owner present.

## QA checklist

- [ ] The owner has signed off a list of in-scope jobs, and each job has one named owner.
- [ ] Each in-scope job has one recording saved in its folder.
- [ ] Each SOP uses every heading from `SOP_TEMPLATE.md`, with no placeholder text left.
- [ ] Each SOP's steps start with a verb and contain one action each.
- [ ] A second person who has never done the job completes it from the SOP alone, with no help from the author.
- [ ] Each gap found in the test run has a change-log entry in the SOP.
- [ ] The "Current" folder holds exactly one SOP per in-scope job, with no duplicate titles.
- [ ] Every SOP is in the client's shared drive, and the client's account is the owner of that drive.
- [ ] No passwords, account secrets, or key values appear in any SOP.
- [ ] The client opens each SOP from the shared drive link without needing Gray Matter's account.

## Handoff

- The client receives: the shared drive folder with the "Current" and "Archive" folders, one SOP per job, the recordings, and the "how to keep it current" note.
- The client owns the shared drive and every file in it. Transfer ownership of any file created under a Gray Matter account before handoff.
- Gray Matter keeps no passwords after handoff. Remove any access Gray Matter was given to the drive and confirm in writing.
- The walkthrough with the owner covers how to find a SOP, how to edit one, and how to log a change.

## Maintenance option

Document upkeep after handoff is optional and quoted after a fit check, based on how many SOPs exist and how often the work changes. No monthly price is published for this service. Confirm the figure in writing before setting it up.
